# 播客初剪与整期制作

使用用户指定的 PodCut 工程；项目根目录为当前工作目录，不依赖固定安装路径。保留源音频、精确字 ID、字界及可复原编辑。读 [编辑规则](references/editorial.md) 后执行；网页 Agent 直接加载同一份规则，并记录版本和内容哈希，不靠用户手工复制提示词。

## 先确定制作选项

- 录音顺序；参考稿可选，支持 DOCX / TXT / MD / SRT / VTT。稿外有效表达照常保留。
- 停顿阈值，是否清理吸气；人声倍速（不变调，配乐原速）。
- 片头：不要精句、用户挑选、或明确授权 Agent 自动挑选；期望精句数。默认不替用户作决定。
- 背景音乐、过场、片尾素材均可选；可从素材库选择或上传。填写音乐先行秒数、背景时长模式及各类音量。已有配乐选择保留，或明确按本次配置重新安排。
- 用户的补充偏好是本次配置，不把一次剪辑选择写成所有人的强制规则。

网页已导入并校准的录音可直接使用“Agent 初剪”。首次使用先绑定兼容 Chat Completions 的模型 API；文字发送到所选服务，录音与配乐留在本机。使用已有服务仍遵循用户已有授权；新服务需由用户选择。API Key 只保存在本机服务配置，不写入工程、提示词或浏览器存储。

## 执行与确认

1. 保存输入快照，先语义候选、再独立复核、最后用声学字界执行。重点检查未完成起句、同义重录及完整插入信息的保护；详见编辑规则。
2. 停顿和吸气使用声学工具；模型不得凭文字生成字界。检查保留字的实际音频覆盖不减少。
3. 有片头需求时生成真实原话候选，显示完整句子、入选理由和试听。用户选择模式必须等其确认；自动选择只在明确授权的选项下执行。候选无效时不能伪造或跳过确认。
4. 按所选顺序复制精句到片头，正文保留原话；插入选定配乐。片头背景的结束随精句实际时长与人声速度确定；片尾在最后发声字之后。
5. 生成结果后再打开。原稿在任务期间变化时拒绝覆盖，保留结果供后续处理。验证片头、人声/音乐独立性、删除接缝、过场与片尾。自动打开后保存成功才称为完成。
6. 用户精修后，以当前工程导出音频、长文和简介时间戳，不沿用旧初剪时间。

导出时先读 [播客文字稿导出规则](references/publication.md)。长文稿直接使用当前剪后正文，只整理段落，不调用 AI 改写、加载个人文风或补写观点。片头复制的精句不重复进入正文；正文中的有效口癖、玩笑、英文和例子保留。简介与时间戳独立按需生成。选材、核查与文章改写交给用户自己的 Agent，不作为网页或本 skill 的默认输出。

命令行整期制作与 `.podcast` 工程格式见 [运行方式](references/workflow.md)。CLI 的默认确认流程仍需用户选定精句后使用 `assemble --confirmed`；网页的自动选择选项不等于 CLI 已获得授权。

## 从精修学习

用户要求总结时，保存当前精修版的只读副本，与明确的初剪版本按 clip ID / word ID 对比。区分新删除、复原、字界、范围、配乐和倍速变化；不能把中间由助手修复的内容归功于人工。缺少完整历史时说明比较基线的限制。

复原的完整句、英文名、连接词和跨词相同字是重要反例。删除的半句和同义重录用于补足漏检。整段故事删减和配乐偏好可能只适用于本期，不能无依据推广。把有证据的通用修正写回编辑规则，并用独立保留案例与应删案例验证；更新规则不重新剪用户精修工程。

吸气检测并非百分之百准确。完成是可打开、可播放、可继续精修的工程，不是计划、提示词文件或后台进程启动。未经用户要求不上传播客平台。
